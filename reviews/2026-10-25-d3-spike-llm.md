# 审查请求：D3 Week 0 Spike CLI（LLM 出题与质检）

## 背景与目标（3–5 行）

D1 工程地基与 D2 领域/数据已关闭，D3 的目标是让 `pnpm eval` 真正跑完
`解析 → 归一化 → 切块 → 考点 → 易错点 → 蓝图扇出 → 单题生成 → 质检 → 发布门禁`，
产出 JSON + 人工复核表，用来回答「这套链路能不能达到计划第十一节的质量门槛」。

本次增量完成的是 LLM 段：Qwen（DashScope 兼容接口）客户端与 SQLite 精确缓存、
版本化 prompt、按难度分层的质检与发布门禁、simhash + 题干精确键去重、报告输出。
**尚未接入真实材料**：工作区里只有合成样本，所以本文件不声称任何质量门槛达标，
只提交可复跑的管道与已知问题。

## 变更范围（文件路径 + 关键符号）

- `qwen-client.ts`
  - `QwenClient.complete()`：预算检查 → 缓存查询 → 请求循环（失败重试上限 3 次）；
    `seed` 在请求前收口到 32 位有符号范围（DashScope 报 `'seed' must be Integer`，见下方自测）。
  - `SqliteLlmCache`：key = `sha256(model|promptVersion|temp|messages)`，命中时 `costCny = 0`。
- `spike.ts`
  - `callStructured()`：zod 失败或非法 JSON 时回灌原始输出 + 错误路径，重试一次；仍失败计入 `StructuredCounters`。
  - `extractKnowledgePoints()`：逐块抽取，`source_quote` 无法定位即丢弃；同名合并（importance/difficulty 取大）。
  - `planSlots()`：`allocateQuestionsPerKp`（domain）+ `typeDistribution`（domain）→ 交错题位。
  - `validateGenerated()`：题型选项数、答案唯一性、判断题标签归一（中文正确/错误、英文 True/False）。
  - `runSlot()`：生成（最多 2 次，带反馈）→ `checkCitation`（domain，权威）→ 精确键 + simhash 去重 →
    质检 → 难度 ≤3 盲解 2/2 / 4–5 给答案反证 → `evaluatePublish(question, checks, applicable)`。
  - `applicableHardChecksFor()`：基础 6 项 + 难度分层 1 项；**`moderation` 显式不在适用集合**（M0 未接入）。
- `run-eval.ts`
  - `--parse-only` 保留原解析复核路径；默认跑完整链路。
  - 打开 `data/qgen.db` 前检查 `llm_cache` 表是否存在，缺表则关闭缓存并告警，不阻塞运行。

### 真实材料暴露并已修复的问题

1. **中文 PDF 抽出 0 个汉字**（`extract.ts`）。pdfjs 没给 `cMapUrl`，Adobe-GB1 等预定义 CMap 取不到字形→unicode 映射，汉字全部丢失：首跑 8,202 字、汉字占比 0.0%、语言判成 `en`。补 `cMapUrl = <pkg>/cmaps/` + `cMapPacked: true` 后 19,769 字、67.3%、替换字符 0 个。**这类论文是 M0 的目标材料，属于 Blocker 级缺陷，已修。**
2. **全半角/空白差异导致引用误杀**（`locate-quote.ts`、`spike.ts`）。该论文英文摘要用**全角逗号**排版（`Confucianism，Buddhism`），模型回抄成 `Confucianism, Buddhism`：定位（忽略空白）成功，`checkCitation` 却判 `mismatch`，整题作废。新增第三档 `folded` 定位（逐码点 NFKC + 弯引号/破折号映射 + 去空白，一对多折叠按码点宽度回算区间），并把「纯空白差异」从引用错误中豁免——`sourceRefs` 存的始终是 `located.quote`（原文切片），语义差异照常拒绝。新增 2 个用例。
3. **考点抽取把多处文字用省略号拼成一个 `source_quote`**（`kp-extract.v1.ts`、`spike.ts`）。真实论文首跑 19 个考点丢 7 个，缓存里的原始响应可证：
   - 「场域的三重空间属性」→ `首先,“场域”是一个实践空间。……其次,“场域”是一个竞争空间。……`
   - 「惯习的双重结构性」→ `…作为实践活动和表象的生成和组织原则起作用……`
   提示词原本已写"不得加省略号"，模型仍犯。改为：提示词补一句显式反例；抽取时定位失败的考点**带着失败样本重抽一次**（只在该块有失败时触发），仍失败才丢弃并告警。

`pnpm check` 复跑：**107 用例全绿**（17 个文件），depcruise 87 模块 / 167 依赖 0 违规；后续缺陷修复后为 **109 用例**。

   当前所有运行都是 77–1651 字的合成样本，知识点目标 15 个达不到，题量与难度分布不具代表性。

3. **simhash 对短文本偏噪声**。实测「换一个词」的题干汉明距离在 2–9 之间，≤3 只能抓住非常接近的变体。
   已补 `stemKey`（折叠空白/标点/大小写）做精确比对本；这是否算对计划"simhash ≤3"的偏离，请裁定。
4. **高难题覆盖为 0**。所有自动发布题的 `difficulty_est` 都是 2–3，`highDifficultyShare = 0`；
   计划要求自动发布题中难度 4–5 占比 ≥15%。这是模型自评偏保守，还是蓝图没有把难度推上去，需要真实材料验证。
5. **`documents` 表未写入**。spike 是文件式 CLI（计划 M0-1 明确"无数据库"），归一化文档只存在内存与
   `normalized.txt`；持久化留给 M0-2 的 worker 阶段。请确认这不与 D2 的 `documents` 要求冲突。
6. **prompt 版本纪律**。`generate-question.v1` 在开发中改过一次（要求解析用 A/B/C/D 而非数字下标；
   改后已复跑验证，见自测第 2 节），
